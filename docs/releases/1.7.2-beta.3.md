# ProxPanel 1.7.2-beta.3 — Docker Monitoring & Alerts

**Status:** GitHub prerelease  
**Channel:** Beta

## 🇫🇷 Français

Cette beta ajoute une vraie supervision Docker en arrière-plan via **Portainer**, indépendante du navigateur.

### Incidents surveillés

- Portainer inaccessible.
- Docker Engine inaccessible.
- Conteneur précédemment actif puis arrêté.
- Healthcheck Docker `unhealthy`.
- Redémarrages répétés.
- CPU conteneur au-dessus du seuil configuré.
- RAM conteneur au-dessus du seuil configuré.
- Pression stockage Docker lorsque Docker expose des données `Used / Total` fiables.
- Stack active partiellement dégradée.

### Fiabilité

- **2 contrôles consécutifs** sont requis par défaut avant d'activer un incident.
- Une erreur temporaire Portainer/Docker n'est jamais transformée en faux « conteneur arrêté ».
- Les incidents ne sont pas renvoyés à chaque poll.
- Un cooldown est appliqué aux réapparitions d'incidents.
- Une notification de récupération est envoyée lorsqu'un incident confirmé disparaît sur un contrôle fiable.
- Si les métriques CPU/RAM deviennent temporairement indisponibles, cela n'est pas interprété comme une récupération.
- Si l'inventaire des stacks est indisponible, ProxPanel conserve l'état d'incident précédent au lieu de conclure à tort que la stack est saine.
- Les actions Stop/Pause/Restart lancées depuis ProxPanel sont temporairement marquées comme intentionnelles.

### Notifications

Les événements Docker peuvent être routés vers :

- Panel ProxPanel ;
- Discord par salon ;
- e-mail ;
- webhook générique ;
- Telegram si configuré.

Les nouveaux types incluent notamment :

- `docker.portainer.unreachable`
- `docker.engine.unreachable`
- `docker.container.stopped`
- `docker.container.unhealthy`
- `docker.container.restarts`
- `docker.resources.cpu`
- `docker.resources.memory`
- `docker.storage.pressure`
- `docker.stack.degraded`
- `docker.recovered`

### Interface

- Incidents Docker visibles directement dans **Docker**.
- Incidents également visibles dans le centre **Notifications**.
- Réglages : activation, nombre de confirmations, cooldown et seuil de redémarrages.
- Laboratoire e-mail enrichi avec les modèles Docker.
- Routage Discord enrichi avec les événements Docker.

### Stockage Docker

La pression stockage n'est affichée que lorsque Docker expose des valeurs de capacité fiables via `DriverStatus`. ProxPanel n'invente pas de capacité si l'information n'est pas disponible.

## 🇬🇧 English

This beta adds real background Docker monitoring through **Portainer**, independent from the browser.

### Monitored incidents

- Portainer unreachable.
- Docker Engine unreachable.
- Previously active container unexpectedly stopped.
- Docker healthcheck `unhealthy`.
- Repeated container restarts.
- Container CPU above the configured threshold.
- Container memory above the configured threshold.
- Docker storage pressure when reliable `Used / Total` capacity data is exposed.
- Partially degraded active stack.

### Reliability

- **2 consecutive checks** are required by default before an incident becomes active.
- Temporary Portainer/Docker API failures never become false “container stopped” alerts.
- Active incidents are not resent on every poll.
- Cooldown is applied to recurring incidents.
- Recovery notifications are emitted when a confirmed incident clears on a reliable check.
- Temporarily unavailable CPU/RAM metrics are not treated as recovery.
- Unavailable stack inventory does not falsely resolve stack incidents.
- Stop/Pause/Restart actions initiated from ProxPanel are temporarily treated as intentional.

### Notifications

Docker events can be routed to Panel, Discord, email, generic webhook and Telegram when configured.

### UI

- Docker incidents shown directly in the Docker workspace.
- Docker incidents also shown in Notifications.
- Monitoring settings for enablement, confirmations, cooldown and restart threshold.
- Docker email templates and Discord routing options.

### Docker storage

Storage pressure is only reported when Docker exposes reliable capacity data. ProxPanel does not fabricate missing capacity information.

## Tests prioritaires / Priority testing

- Stop a container outside ProxPanel and confirm an alert only after the configured number of checks.
- Stop a container from ProxPanel and confirm no unexpected-stop alert is generated.
- Break Portainer connectivity temporarily and verify no container-stop false positives.
- Trigger an unhealthy healthcheck.
- Trigger repeated restarts.
- Verify recovery notification.
- Verify Discord routing and email templates.
- Verify Docker alerts remain visible after browser refresh.
