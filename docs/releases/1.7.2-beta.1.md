# ProxPanel 1.7.2-beta.1 — Repository Foundation & Portainer Core

**Status:** GitHub prerelease  
**Channel:** Beta

## 🇫🇷 Français

Cette version ouvre la série **1.7.2** avec une nouvelle orientation : ProxPanel devient progressivement une console d'exploitation HomeLab couvrant Proxmox et Docker.

### Portainer devient la première intégration officielle

Docker est connecté à ProxPanel **exclusivement via Portainer** dans cette série.

- Portainer **Community Edition** est la cible de validation prioritaire.
- Portainer **Business Edition** reste compatible lorsque les mêmes endpoints API sont disponibles.
- L'interface et le code utilisent le nom générique **Portainer** : aucune dépendance n'est volontairement verrouillée sur CE.
- Aucun montage de `/var/run/docker.sock` n'est requis dans ProxPanel.
- Une API Key / Access Token Portainer est utilisée et stockée chiffrée localement.
- TLS est validé par défaut ; les certificats auto-signés peuvent être autorisés explicitement.

### Administration → Intégrations

Nouvelle rubrique Portainer dédiée :

- URL Portainer ;
- nom de l'instance ;
- API Key / Access Token ;
- option certificat auto-signé ;
- test de connexion avant enregistrement ;
- détection de la version et de l'édition lorsqu'elles sont exposées par l'API ;
- découverte automatique des environnements ;
- diagnostic de connexion ;
- suppression et nouveau test de l'intégration.

### Nouvelle page Docker

Le menu **Docker** n'apparaît que lorsqu'au moins un Portainer est configuré.

La première vue affiche :

- instances Portainer configurées ;
- environnements découverts ;
- environnement joignable/injoignable ;
- détection Docker Standalone ;
- version Docker ;
- hostname ;
- OS / architecture ;
- CPU ;
- RAM ;
- nombre total de conteneurs ;
- conteneurs running ;
- conteneurs stopped ;
- conteneurs healthy/unhealthy.

Une instance Portainer en erreur n'empêche pas les autres de rester visibles.

### Périmètre beta.1

**Docker Standalone** est le premier type d'environnement pris en charge.

Docker Swarm peut être découvert et identifié mais n'est pas encore une cible opérationnelle de beta.1.

Les fonctionnalités suivantes arrivent dans **1.7.2-beta.2** :

- inventaire détaillé des conteneurs ;
- logs ;
- inspect ;
- console/exec ;
- actions start/stop/restart ;
- stacks Docker Compose ;
- actions de stack.

### PBS

Proxmox Backup Server reste une intégration **optionnelle**, prévue pour **1.7.2-beta.6**.

Aucun menu PBS permanent n'est ajouté tant qu'un PBS n'est pas configuré.

### Foundation / qualité

- `ROADMAP.md`, README FR/EN, HISTORY et politique de release ont été remis à niveau.
- L'ancien `proxpanel-update.json` a été retiré au profit du seul `release.json`.
- La CI exécute maintenant des tests fonctionnels Node en plus des vérifications de syntaxe et du build Docker.
- Des tests empêchent notamment la régression du faux positif backup :
  - backup de 24 h avec seuil 36 h = OK ;
  - backup > 36 h = stale ;
  - inventaire non fiable = aucune conclusion d'absence.
- Premiers tests de classification Docker/Portainer.

## 🇬🇧 English

This release starts the **1.7.2** series with a new direction: ProxPanel progressively becomes a HomeLab operations console spanning both Proxmox and Docker.

### Portainer becomes the first official integration

Docker is connected to ProxPanel **exclusively through Portainer** in this series.

- Portainer **Community Edition** is the primary validation target.
- Portainer **Business Edition** remains compatible when the same API endpoints are available.
- The UI and implementation use the generic **Portainer** name: nothing is intentionally locked to CE.
- ProxPanel does not require mounting `/var/run/docker.sock`.
- A Portainer API Key / Access Token is used and stored encrypted locally.
- TLS is validated by default; self-signed certificates can be explicitly allowed.

### Administration → Integrations

Dedicated Portainer integration workflow:

- Portainer URL;
- instance name;
- API Key / Access Token;
- self-signed certificate option;
- connection test before saving;
- version/edition detection when exposed by the API;
- automatic environment discovery;
- connection diagnostics;
- integration retest and removal.

### New Docker page

The **Docker** menu only appears when at least one Portainer integration is configured.

The first overview shows:

- configured Portainer instances;
- discovered environments;
- reachable/unreachable environment state;
- Docker Standalone detection;
- Docker version;
- hostname;
- OS / architecture;
- CPU;
- RAM;
- total containers;
- running containers;
- stopped containers;
- healthy/unhealthy containers.

One failing Portainer instance does not hide the other configured instances.

### beta.1 scope

**Docker Standalone** is the first supported environment type.

Docker Swarm may be discovered and identified but is not yet an operational beta.1 target.

The following features are planned for **1.7.2-beta.2**:

- detailed container inventory;
- logs;
- inspect;
- console/exec;
- start/stop/restart actions;
- Docker Compose stacks;
- stack actions.

### PBS

Proxmox Backup Server remains an **optional** integration planned for **1.7.2-beta.6**.

No permanent PBS navigation is shown until PBS is configured.

### Foundation / quality

- `ROADMAP.md`, FR/EN README, HISTORY and release policy were refreshed.
- Legacy `proxpanel-update.json` was removed in favor of root `release.json`.
- CI now runs Node functional tests in addition to syntax checks and Docker build.
- Regression tests protect the backup false-positive fix:
  - 24-hour backup with a 36-hour threshold = OK;
  - backup older than 36 hours = stale;
  - unreliable inventory = no missing-backup conclusion.
- Initial Docker/Portainer classification tests.

## Tests prioritaires / Priority testing

- Portainer CE with one Docker Standalone environment.
- Portainer CE with several Docker environments.
- Portainer behind HTTPS with a valid certificate.
- Portainer with a self-signed certificate.
- Invalid API Key.
- Portainer temporarily unreachable.
- Multiple Portainer instances where one is unreachable.
- Portainer Business Edition if available.
- iPhone/PWA and tablet Docker overview.
- Light and Dark themes.
- Upgrade from `1.7.1-beta.10`.
