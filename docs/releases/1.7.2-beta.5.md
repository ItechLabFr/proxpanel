# ProxPanel 1.7.2-beta.5 — Docker Image & Update Management

## Français

Cette bêta ajoute le premier workflow complet de gestion des mises à jour d’images Docker dans ProxPanel, exclusivement via Portainer.

### Images & Updates
- Nouvel onglet **Images & Updates** par environnement Docker.
- Images utilisées, inutilisées et dangling.
- Relations image → conteneurs → stacks.
- Tag, ID d’image, digest local et digest distant lorsque disponibles.
- Statuts distincts : **À jour**, **Mise à jour disponible**, **Image téléchargée · redeploy requis**, **État distant inconnu**.

### Workflow sécurisé
- Vérification distante par digest lorsque Docker/registre l’autorisent.
- Pull manuel, sans redémarrage implicite.
- Aperçu des cibles avant redeploy.
- Redeploy de stack avec confirmation et contrôle de santé.
- Remplacement guidé des conteneurs autonomes avec conservation temporaire de l’ancien conteneur et tentative de rollback si le nouveau conteneur échoue.
- Refus automatique pour un conteneur autonome avec IP/MAC statique ou réseau avancé.
- Aucun prune global automatique.

### Planification
- Contrôle automatique des images optionnel, désactivé par défaut.
- Fenêtres de maintenance Docker configurables.
- Une mise à jour planifiée n’est exécutée que si elle a été **explicitement ajoutée à la file**.
- Aucun comportement Watchtower : ProxPanel ne sélectionne jamais tout seul des conteneurs à redeployer.

### Exploitation
- Historique des checks, pulls, redeploys, suppressions et actions planifiées.
- Audit des opérations.
- Notifications pour les nouvelles images et les échecs de mise à jour.
- Données fictives déterministes pour la démo publique.
- Interface responsive téléphone/tablette/PWA.

## English

This beta adds ProxPanel's first complete Docker image update workflow, exclusively through Portainer.

### Images & Updates
- New **Images & Updates** tab per Docker environment.
- Used, unused and dangling images.
- Image → container → stack relationships.
- Tag, image ID, local digest and remote digest when available.
- Separate states: **Up to date**, **Update available**, **Image pulled · redeploy required**, and **Remote state unknown**.

### Safe workflow
- Remote digest checks when Docker/registry data is reliable.
- Manual pull with no implicit restart.
- Pre-redeploy target preview.
- Stack redeploy with confirmation and health verification.
- Guided standalone-container replacement with temporary preservation of the old container and rollback attempt when the new container fails.
- Automatic refusal for standalone containers with static IP/MAC or advanced networking.
- No automatic global prune.

### Scheduling
- Optional automatic image checks, disabled by default.
- Configurable Docker maintenance windows.
- A scheduled update runs only after an authorized user **explicitly queues it**.
- No Watchtower-style behavior: ProxPanel never chooses production containers to redeploy by itself.

### Operations
- Check, pull, redeploy, removal and scheduled-action history.
- Audit trail.
- Notifications for available images and update failures.
- Deterministic public-demo fixtures.
- Responsive phone/tablet/PWA UI.

## Safety / Sécurité

Docker remains managed through the Portainer API only. ProxPanel does not require direct access to `/var/run/docker.sock`. Portainer CE is the primary validation target.
