# ProxPanel 1.7.2-beta.9.1 — Security & RBAC hotfix

## FR

Cette version corrige plusieurs contournements d’autorisation découverts dans la série 1.7.2-beta.9.

- RBAC centralisé et fail-closed pour toutes les routes API mutatives.
- Change Center protégé par `changes.manage` et aligné sur l’allowlist de configuration VM/LXC.
- Actions PBS `verify`, `prune`, `sync` et `gc` protégées par `pbs.control`.
- Automatisations protégées par `automations.view`, `automations.manage` et `automations.run`, avec revérification des droits machine/Docker/backup à l’exécution.
- Scénarios planifiés liés à leur propriétaire et refusés si son compte ou ses permissions ne sont plus valides.
- Permissions dédiées pour dépendances, groupes/vues et actions Wazuh.
- Rôle Operator réparé : les opérations légitimes sous `/api/servers/:id/*` ne sont plus bloquées par le garde admin générique.
- `X-Forwarded-For`, `X-Forwarded-Proto` et `X-Forwarded-Host` acceptés uniquement depuis un proxy approuvé.
- Content-Security-Policy activée.

### Reverse proxy

Si TLS est terminé par Nginx Proxy Manager, Traefik, Caddy ou un autre proxy, définir :

```env
PROXPANEL_TRUSTED_PROXIES=10.10.20.5,172.18.0.0/16
```

Loopback (`127.0.0.1` et `::1`) est toujours approuvé.

## EN

This release fixes multiple authorization bypasses found in 1.7.2-beta.9.

- Centralized fail-closed RBAC for mutating API routes.
- Change Center requires `changes.manage` and uses the normal VM/LXC configuration allowlist.
- PBS verify/prune/sync/gc requires `pbs.control`.
- Automations use dedicated view/manage/run permissions and re-check machine, Docker and backup permissions at execution time.
- Scheduled automations are tied to their owner and fail closed if the owner is disabled or loses permissions.
- Operator access below `/api/servers/:id/*` is restored without granting server administration.
- Forwarded headers are honored only from explicitly trusted proxies.
- A Content-Security-Policy is emitted.
