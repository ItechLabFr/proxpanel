# ProxPanel 1.7.1-beta.2 — Infrastructure UX & Monitoring

**Status:** Planned / In development after beta.1 validation  
**Channel:** Beta

This release intentionally groups four major infrastructure-facing improvements into one beta.

## 🇫🇷 Français

### 1. Stockage des VM Windows/Linux

Pour chaque VM QEMU, ProxPanel doit afficher :

- disques virtuels configurés dans Proxmox ;
- capacité virtuelle configurée ;
- partitions, volumes et points de montage remontés par le QEMU Guest Agent ;
- taille totale, espace utilisé, espace libre et pourcentage d’occupation ;
- état de disponibilité de la donnée.

La présentation doit clairement différencier la capacité disque Proxmox de l’occupation réelle du système invité.

Si l’occupation ne peut pas être récupérée, afficher la cause : Guest Agent absent, arrêté, timeout, non supporté, permissions insuffisantes ou données filesystem indisponibles. Ne jamais transformer une absence de donnée en faux zéro.

### 2. Refonte multi-nœuds

- supprimer les barres de ressources doublées ;
- supprimer les cartes compressées illisibles ;
- hiérarchie claire cluster/groupe → nœud → ressources ;
- CPU, RAM, température, stockage et état réseau lisibles pour chaque nœud ;
- mise en page adaptative plutôt qu’une compression permanente ;
- cohérence entre vues regroupées et individuelles.

### 3. Responsive global

Audit complet de l’application sur iPhone/PWA, tablette/iPad et desktop : Dashboard, Machines, Nœuds, Monitoring, Stockage, Backups, Tâches, Dépendances, Changements, Maintenance, Updates PVE, Automatisations, Notifications, Utilisateurs, Administration et consoles.

Points obligatoires : menus accessibles, modales adaptées, tableaux utilisables, boutons tactiles suffisamment grands, gestion du clavier mobile, safe-area iPhone et aucun contenu important hors écran.

### 4. Monitoring complet

La page Monitoring doit rendre lisibles : disponibilité API Proxmox, latence, état des nœuds, CPU/load, RAM, stockage, réseau, température, diagnostic lm-sensors, Guest Agent lorsque pertinent, dernière actualisation, données périmées et états warning/critical/unavailable.

Les erreurs techniques détaillées restent accessibles, mais l’état principal doit être compréhensible sans connaître l’API Proxmox.

## 🇬🇧 English

### 1. Windows/Linux VM storage

For every QEMU VM, expose Proxmox-configured virtual disks and capacity plus guest filesystem information from QEMU Guest Agent when available: partitions, volumes, mount points, total size, used space, free space and usage percentage.

The UI must clearly separate hypervisor disk capacity from guest filesystem usage. When usage cannot be retrieved, show an explicit reason instead of a misleading zero or estimate.

### 2. Multi-node redesign

Remove duplicated resource bars, avoid compressed node cards, establish a clear cluster/group → node → resource hierarchy, and keep CPU, RAM, temperature, storage and connectivity readable for every node.

### 3. Global responsive audit

Review the complete application on iPhone/PWA, tablet/iPad and desktop, including navigation, modals, tables, buttons, forms, consoles and all main pages.

### 4. Monitoring redesign

Monitoring should clearly expose API reachability, latency, node state, CPU/load, RAM, storage, network, temperatures, lm-sensors diagnostics, relevant Guest Agent availability, last refresh time, stale data and warning/critical/unavailable states.

## Acceptance criteria

- QEMU VM storage provides a useful explicit state on Windows and Linux.
- Guest Agent absence is clearly reported and never converted into fake usage data.
- At least two nodes remain readable in grouped views.
- Main workflows are usable on iPhone portrait, tablet portrait and desktop.
- Monitoring clearly distinguishes healthy, warning, critical, unavailable and stale.
- New user-facing functionality is available in both French and English.
- Existing LXC storage, temperature, login/MFA, console and fast PWA startup behavior must not regress.
