# ProxPanel 1.7.2-beta.9 — Health Center 2.0

## Français

### Health Center 2.0

La page « Problèmes » devient un véritable centre de gestion des incidents.

Chaque warning dispose désormais d’un cycle de vie persistant :

- **Actif** — problème détecté et non traité ;
- **Validé** — un administrateur a pris connaissance du problème ;
- **Snoozé** — masqué temporairement ;
- **Résolu** — traité manuellement ou rétabli automatiquement ;
- **Effacé** — retiré de la vue active sans supprimer l’événement source ;
- **Risque accepté** — condition connue et volontairement ignorée.

Actions disponibles :

- Valider ;
- Résoudre ;
- Snooze 1 h / 4 h / 24 h / 7 jours ;
- Effacer de la vue active ;
- Ignorer une cible pour un type de warning ;
- Réouvrir ;
- actions groupées sur plusieurs incidents.

### Sources unifiées

Le Health Center centralise maintenant les incidents provenant de plusieurs moteurs sans supprimer ni remplacer leurs données natives :

- **Proxmox / Backups** — nœuds, stockage, ressources, tâches et couverture de sauvegarde ;
- **Docker / Portainer** — Portainer/Engine injoignable, conteneur arrêté ou unhealthy, redémarrages répétés, CPU/RAM, stockage et stack dégradée ;
- **Wazuh** — état de l’intégration, agents déconnectés, CVE critiques/élevées regroupées par CVE + logiciel avec machines et versions concernées, alertes importantes et FIM sensible quand activé ;
- **PBS** — état de l’intégration, datastores presque pleins/critiques, tâches récentes en échec et vérifications de sauvegarde en erreur.

Chaque source est identifiable dans l’incident, l’historique et les filtres. Une condition qui disparaît réellement passe automatiquement en **Résolu**.

Le widget Health Center du Dashboard utilise le même inventaire unifié.

### Risques acceptés

Les alertes attendues peuvent être exclues sans désactiver toute la supervision.

Exemple : une VM/LXC volontairement sans sauvegarde peut être marquée comme risque accepté uniquement pour le warning **Machine non protégée**.

Les exclusions :

- sont persistantes après redémarrage ;
- conservent la source, le serveur, la cible, le type d’alerte et la raison ;
- restent visibles dans une vue dédiée ;
- sont inscrites dans l’historique et l’audit.

### Réouverture automatique

Une action manuelle ne falsifie jamais l’état réel de l’infrastructure.

Si un warning est marqué résolu ou effacé alors que la condition existe toujours, ProxPanel peut le réouvrir après le cooldown configuré.

Si la condition disparaît réellement, l’incident passe automatiquement en résolu.

### Historique des incidents

Le Health Center conserve :

- première détection ;
- dernier contrôle ;
- état courant ;
- utilisateur ayant changé l’état ;
- commentaire / raison ;
- récupération automatique ;
- nombre de réouvertures ;
- historique des transitions.

### Audit 2.0

- recherche plein texte ;
- filtre utilisateur ;
- filtre action ;
- filtre résultat ;
- détails techniques consultables ;
- export **CSV** ;
- export **JSON** ;
- actions Health Center enregistrées dans l’audit.

### Sessions actives

Administration → Utilisateurs & sécurité affiche maintenant les sessions ProxPanel actives :

- utilisateur ;
- appareil / OS détecté ;
- adresse IP ;
- dernière activité ;
- expiration ;
- indication de la session courante ;
- révocation immédiate.

La déconnexion normale révoque également la session côté serveur.

### Permissions

Nouvelle permission pour les rôles personnalisés :

`health.manage`

Elle autorise la modification de l’état des incidents sans donner accès aux réglages administrateur complets.

### Interface

- nouvel écran Health Center responsive ;
- onglets Actifs / Validés / Snoozés / Résolus / Effacés / Risques acceptés / Historique ;
- compteurs par état et sévérité ;
- recherche ;
- filtre source Proxmox / Docker / Wazuh / PBS ;
- filtre critique / warning ;
- sélection multiple ;
- actions rapides sur chaque incident ;
- intégration au widget Dashboard.

## English

### Health Center 2.0

The old Problems page becomes a persistent incident-management center.

Incident states:

- Active;
- Acknowledged;
- Snoozed;
- Resolved;
- Dismissed;
- Accepted risk.

Actions include acknowledge, resolve, snooze, dismiss, ignore/accept risk, reopen and bulk operations.

Accepted-risk rules persist across restarts and never delete the original Proxmox/Portainer/PBS/Wazuh source event.

Persistent conditions can automatically reopen after the configured cooldown, while genuinely recovered conditions are automatically resolved.

### Unified sources

Health Center now centralizes native incident state from:

- **Proxmox / backups**;
- **Docker / Portainer**;
- **Wazuh** integration health, disconnected agents, critical/high CVEs, important alerts and optional sensitive FIM events;
- **PBS** integration health, datastore pressure, failed tasks and failed verification states.

Each incident keeps its source identity and automatically moves to **Resolved** when the underlying condition clears. The Dashboard Health Center widget uses the same unified inventory.

### Audit 2.0

- full-text search;
- user/action/result filters;
- technical context;
- CSV export;
- JSON export;
- Health Center state transitions in audit history.

### Active sessions

Administrators can list and revoke active ProxPanel sessions from Users & Security.

### Permissions

New custom-role permission: `health.manage`.

### Distribution

When published, beta.9 will continue to produce:

- universal Docker/LXC OTA ZIP;
- full package ZIP;
- native Debian 13 LXC package.

Docker Hub publication remains manual.
