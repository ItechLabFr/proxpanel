# ProxPanel 1.7.1-beta.10 — Backup Reliability & Stabilization

**Status:** GitHub prerelease  
**Channel:** Beta

## 🇫🇷 Français

Cette version corrige les faux positifs de sauvegarde observés avec des sauvegardes quotidiennes et une rétention de plusieurs jours.

### Détection des sauvegardes

- Un stockage/PBS temporairement inaccessible n'est plus interprété comme « aucun backup trouvé ».
- ProxPanel conserve le dernier inventaire backup valide en mémoire pour servir de preuve pendant une indisponibilité temporaire.
- Une absence de sauvegarde n'est jamais déduite d'un inventaire partiel ou périmé.
- Le VMID est récupéré depuis le `volid` si Proxmox ne fournit pas directement le champ `vmid`.
- Les tâches `vzdump` réussies sont utilisées comme preuve complémentaire.
- Si une tâche `vzdump` réussie est plus récente que l'inventaire stockage, elle devient la référence de dernière sauvegarde.
- ProxPanel compte maintenant les points de restauration détectés par VM/LXC.

### Alertes

- Le seuil par défaut reste de **36 h**, adapté à une sauvegarde quotidienne d'environ 24 h.
- **Sauvegarde attendue absente** nécessite désormais **2 contrôles consécutifs fiables** avant notification.
- Un contrôle partiel ou non fiable remet la confirmation à zéro au lieu d'envoyer une fausse alerte.
- Le même incident n'est plus renvoyé en boucle tant qu'une vraie récupération n'a pas été observée.
- L'état de l'inventaire backup est enregistré dans l'état interne des alertes pour faciliter le diagnostic.

### Rétention

Avec une rétention de 7 jours, ProxPanel peut désormais associer plusieurs points de restauration à une même VM/LXC au lieu de ne raisonner que sur une seule occurrence.

## 🇬🇧 English

This release fixes backup false positives seen with daily backups and multi-day retention policies.

### Backup detection

- A temporarily unavailable storage/PBS endpoint is no longer treated as “no backup found”.
- ProxPanel keeps the last valid backup inventory in memory as evidence during temporary outages.
- Backup absence is never inferred from partial or stale inventory data.
- VMID is recovered from `volid` when Proxmox does not expose `vmid` directly.
- Successful `vzdump` tasks are used as additional backup evidence.
- If a successful `vzdump` task is newer than the storage inventory, it becomes the last-backup reference.
- ProxPanel now counts detected restore points per VM/LXC.

### Alerts

- The default stale threshold remains **36 hours**, appropriate for daily backups around 24 hours old.
- **Expected backup missing** now requires **2 consecutive reliable checks** before notification.
- Partial or unreliable checks reset confirmation instead of sending a false alert.
- The same incident is no longer repeatedly sent until a real recovery is observed.
- Backup inventory state is stored in the alert state for easier diagnostics.

### Retention

With a 7-day retention policy, ProxPanel can now associate multiple restore points with the same VM/LXC instead of reasoning from a single occurrence.

## Tests prioritaires / Priority testing

- VM/LXC sauvegardée quotidiennement avec dernière sauvegarde autour de 24 h.
- Rétention 7 jours avec plusieurs points de restauration.
- Coupure temporaire d'un stockage backup/PBS pendant un poll.
- VMID présent uniquement dans le `volid`.
- Tâche `vzdump` réussie récente mais inventaire stockage momentanément indisponible.
- Absence réelle confirmée sur deux polls consécutifs.
- Vérification qu'une même alerte Discord n'est pas répétée en boucle.
