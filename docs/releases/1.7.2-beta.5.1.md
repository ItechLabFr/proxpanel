# ProxPanel 1.7.2-beta.5.1 — 2FA Strong Re-authentication Security Hotfix

## Français

Cette version corrige l’issue **#18** concernant la désactivation de la double authentification depuis une session déjà ouverte.

### Sécurité 2FA
- Une session active ne suffit plus pour désactiver la 2FA.
- L’utilisateur doit saisir son **mot de passe actuel** et un **code TOTP actuel**.
- Pour désactiver la 2FA d’un autre compte, l’administrateur confirme l’action avec **ses propres facteurs**.
- Un administrateur sans 2FA active ne peut pas réinitialiser la 2FA d’un autre utilisateur.
- Après 5 ré-authentifications échouées dans une fenêtre de 15 minutes, les tentatives sont temporairement bloquées.
- Les erreurs de validation restent génériques afin de ne pas exposer quel facteur a échoué.
- Les succès et échecs sont consignés dans l’audit.
- Si la messagerie ProxPanel est configurée, le propriétaire du compte reçoit un e-mail de sécurité après la désactivation.

### Interface
- Le simple bouton de confirmation est remplacé par une modale de ré-authentification.
- La modale demande le mot de passe actuel et le code Authenticator.
- Une réinitialisation administrateur précise que les facteurs demandés sont ceux de l’administrateur connecté.

### Architecture
L’issue **#19** a également été étudiée et documentée dans :

`docs/architecture/frontend-framework-evaluation.md`

Décision actuelle : **migration React/Vue/Vite reportée pour la série 1.7.2**. Le framework améliorerait surtout la maintenabilité et la vélocité du développement front, mais ne sécurise pas les sessions/API à la place du backend et imposerait actuellement une réécriture et une campagne de régression importantes.

## English

This release fixes **issue #18**, where an already-authenticated session could disable two-factor authentication without fresh proof of factor possession.

### 2FA security
- An active session alone is no longer enough to disable 2FA.
- The acting user must provide their **current password** and a **current TOTP code**.
- When disabling 2FA for another account, an administrator confirms the operation with **their own factors**.
- Administrators without 2FA enabled cannot reset another user’s 2FA.
- Five failed strong re-authentication attempts inside 15 minutes temporarily block further attempts.
- Validation failures remain generic so the failed factor is not disclosed.
- Success and failure events are written to the audit log.
- When ProxPanel mail is configured, the account owner receives a security email after 2FA is disabled.

### UI
- The previous simple confirmation is replaced with a strong re-authentication modal.
- The modal requests the current password and Authenticator code.
- Administrative resets clearly state that the connected administrator’s factors are required.

### Architecture
**Issue #19** was also evaluated and documented in:

`docs/architecture/frontend-framework-evaluation.md`

Current decision: **React/Vue/Vite migration deferred for the 1.7.2 series**. A framework would mainly improve frontend maintainability and development velocity, but it would not replace backend session/API security and would currently require a broad rewrite and regression pass.
