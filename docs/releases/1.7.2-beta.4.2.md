# ProxPanel 1.7.2-beta.4.2 — Mail Diagnostics & Logs

**Status:** GitHub prerelease  
**Channel:** Beta

## 🇫🇷 Français

Cette version complète la série beta.4 avec des **e-mails d'alerte réellement exploitables pour le diagnostic**.

### E-mails warning / critical

Pour les événements d'avertissement et d'erreur, l'e-mail peut maintenant afficher :

- la source technique de l'événement ;
- le serveur / cluster ;
- la cible ;
- l'horodatage ;
- les faits et valeurs qui ont déclenché l'alerte ;
- la recommandation ProxPanel ;
- l'UPID Proxmox lorsqu'il existe ;
- un bloc **Détails techniques / Logs** ;
- les dernières lignes du log d'une tâche Proxmox en erreur ;
- les dernières lignes du log d'une sauvegarde `vzdump` en erreur ;
- un extrait des logs d'un conteneur Docker lors d'un incident conteneur, lorsque Portainer permet de les récupérer ;
- le message d'erreur API pour les incidents Portainer / Docker Engine.

### Sécurité

Avant insertion dans l'e-mail, ProxPanel filtre notamment :

- Authorization / Bearer ;
- API keys ;
- tokens ;
- mots de passe ;
- secrets / client secrets ;
- tickets Proxmox ;
- cookies.

Les données techniques sont volontairement limitées et tronquées pour éviter des e-mails trop volumineux.

### Comportement

Lorsqu'aucun log spécifique n'est disponible, ProxPanel affiche au minimum la **source technique** et les informations déjà connues de l'événement.

Cette version reste un **patch beta.4.x** : le contenu de la **beta.5 — Docker Image & Update Management** reste inchangé dans la roadmap.

## 🇬🇧 English

This patch makes warning and critical email notifications more useful for troubleshooting.

Emails can now include:

- technical source;
- server / cluster and target;
- timestamp;
- triggering facts and metrics;
- recommendation;
- Proxmox UPID when available;
- a **Technical details / Logs** section;
- recent Proxmox task log lines;
- recent failed `vzdump` log lines;
- Docker container log excerpts for container incidents when available through Portainer;
- Portainer / Docker Engine API error messages.

Sensitive values such as authorization headers, API keys, tokens, passwords, secrets, Proxmox tickets and cookies are redacted before email generation.

This remains a **beta.4.x patch** and does not consume or replace the beta.5 roadmap scope.

## Tests prioritaires / Priority testing

- Simulate a failed Proxmox task and verify the email contains the UPID and log excerpt.
- Trigger a failed backup and verify the last `vzdump` log lines are present.
- Trigger a Docker unhealthy/stopped incident and verify container logs are included when available.
- Break Portainer connectivity and verify the technical API error appears.
- Verify secrets/API keys/tokens are never visible in delivered emails.
- Verify normal informational/recovery emails remain concise.
