# ProxPanel 1.7.2-beta.2 — Docker Containers & Stacks

**Status:** GitHub prerelease  
**Channel:** Beta

## Français

Cette beta transforme l'intégration Portainer de la beta.1 en un véritable espace d'exploitation Docker.

### Conteneurs

- Inventaire par environnement Portainer.
- Nom, image, état, health, statut/uptime, ports, réseaux et stack associée.
- Détails conteneur avec statistiques CPU/RAM en temps réel quand Docker les fournit.
- Inspect filtré : les variables d'environnement et les champs sensibles sont masqués.
- Logs Docker directement dans ProxPanel.
- Exec non interactif via Portainer → Docker.
- Actions :
  - Start
  - Stop
  - Restart
  - Pause
  - Resume

### Stacks

- Inventaire des stacks Portainer du Docker Standalone sélectionné.
- État actif/arrêté.
- Source Git ou Compose.
- Nombre de conteneurs associés.
- Noms des variables d'environnement visibles, **jamais leurs valeurs**.
- Actions :
  - Start
  - Stop
  - Redeploy avec pull des images

Pour une stack Git, ProxPanel utilise le redeploy Git de Portainer. Pour une stack Compose locale, ProxPanel recharge son contenu actuel et demande un redeploy avec `PullImage=true` et `Prune=false`.

### Sécurité

- Docker reste accessible uniquement via Portainer.
- Aucun montage de `/var/run/docker.sock`.
- Les actions Docker sont limitées aux comptes opérateur/administrateur côté serveur.
- Un compte en lecture seule conserve uniquement la consultation, les détails et les logs.
- Chaque action disruptive est ajoutée au journal d'audit.
- Les commandes Exec ne sont pas enregistrées en clair dans l'audit.
- Les identifiants d'environnement/conteneur/stack sont validés côté serveur.

### Mobile

Les vues Containers & Stacks se recomposent sur téléphone/tablette avec cartes, métriques et actions tactiles.

### OTA

Le correctif de packaging `1.7.2-beta.1.1` est conservé :
- ZIP OTA complet ;
- dépendances locales incluses ;
- smoke-test réel du ZIP extrait dans la CI avant publication.

## English

This beta turns the beta.1 Portainer integration into a real Docker operations workspace.

### Containers

- Inventory per Portainer environment.
- Name, image, state, health, status/uptime, ports, networks and associated stack.
- Container details with real-time CPU/RAM statistics when provided by Docker.
- Filtered Inspect: environment variables and sensitive fields are redacted.
- Docker logs directly in ProxPanel.
- Non-interactive Exec through Portainer → Docker.
- Start, Stop, Restart, Pause and Resume actions.

### Stacks

- Portainer stack inventory for the selected Docker Standalone environment.
- Active/stopped state.
- Git or Compose source.
- Associated container count.
- Environment variable names are visible, **never their values**.
- Start, Stop and Redeploy actions.

Git stacks use Portainer's Git redeploy endpoint. Local Compose stacks are redeployed from their existing content with `PullImage=true` and `Prune=false`.

### Security

- Docker remains accessible only through Portainer.
- No `/var/run/docker.sock` mount.
- Docker actions require operator/admin permission server-side.
- Read-only users retain view, details and logs only.
- Every disruptive action is added to the audit log.
- Exec commands are not stored in clear text in the audit log.
- Environment/container/stack identifiers are validated server-side.

### OTA

The `1.7.2-beta.1.1` packaging fix remains in place, including the extracted OTA smoke-test in CI.
